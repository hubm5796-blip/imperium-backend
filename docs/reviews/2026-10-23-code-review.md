# Code Review: romanica-backend (2026-10-23)

> **Repo:** Romanica-MC/romanica-backend · **Reviewed commit:** `6c69f05` (master) · **Method:** static review of working tree at HEAD
> Severities: **P0** = broken now · **P1** = likely bug / security hole · **P2** = design debt · **P3** = nice-to-have

## Project Snapshot

Backend for Romanica/ImperiumMC (Rome-themed Minecraft prison server): a Hono/TypeScript API deployed as a Cloudflare Worker serving the website, launcher, and store, plus a gateway-less Discord bot (HTTP interactions + cron). Data plane: Supabase Postgres via Hyperdrive (web-owned tables), direct reads of the live game MySQL via a hand-rolled wire client over `cloudflare:sockets`, D1 for backend-only caches, R2 for gallery images, and an HMAC-signed command bus (MySQL tables, Redis fallback) to the game plugin. Store/real-money goes through PayNow (checkout sessions + signed webhooks). ~38k lines of TS across 241 tracked files, 71 test files / 633 tests (all passing, verified), 47 commits in the last month — very active, with an unusually disciplined 11-round documented audit history under `docs/audit/`.

## Architecture Assessment

The trust model is explicitly designed, not accreted: a single `resolvePrincipal` (session cookie → bearer API key → bot/service token → anonymous) feeds named gates (`requireSelfOrDelegated`, `requireMcIdentity`, `requireStaffRole`) as the only sanctioned entry points (`src/middleware/gates.ts`). Two-tier secrets split bot/service capabilities; delegated identity assertions require the service token specifically. Real-money fulfillment is a three-layer idempotency design (D1 dispatch claims keyed by line index, plugin-side registry dedupe, 500-on-failure so PayNow retries), and currency purchases never trust the backend: the backend only enqueues HMAC-signed `web_queue` rows that the plugin re-validates against the catalog before withdrawing Denarius (`src/api/expansion/webqueue.ts`, `webshop.ts`). The main architectural debt is surface, not structure: `src/api/routes.ts` is 3,535 lines of v1 routes with inline per-route auth conventions alongside the v2 sub-app's uniform gates, and DB schema lives in three places (plugin-owned Postgres, 3 formal D1 migrations, and runtime `CREATE TABLE IF NOT EXISTS` for at least six more D1 tables).

## Strengths

- **Webhook security done right**: PayNow HMAC-SHA256 over `timestamp.body`, 5-minute replay window, timing-safe compare across per-subscription secrets (`src/paynow/webhookVerify.ts`); Discord Ed25519 `verifyKey` before any parsing (`src/bot/interactions.ts:31-40`); vote callbacks keyed per-site with timing-safe compare (`src/api/expansion/webshop.ts:38-43`).
- **Fulfillment idempotency with a release-on-failure path**: dispatch claims are `INSERT … ON CONFLICT DO NOTHING` keyed `(order_id, line_index:product:qty:target)`, and a failed dispatch *deletes* the claim so a transient plugin outage can't permanently eat a paid line (`src/paynow/fulfillment.ts:261-295, 385-404`). Cancel-path webhook failures deliberately 500 so PayNow retries; renewal failures deliberately 200 to avoid retry storms (`src/api/routes.ts:2432-2517`).
- **JWT hygiene beyond the default**: HS256 pinned (alg-confusion blocked), `authMethod` allowlist, lifetime caps enforced against `iat` regardless of `exp` (kills the forwarded-400-day-token class), separate `aud` families so client tokens and session tokens can't replay cross-context (`src/auth/jwt.ts:62-124, 163-185`).
- **Client auth is the real Mojang handshake**: 20-byte single-use challenges consumed atomically before Mojang is even contacted, plus an explicit username↔profile cross-check (`src/api/clientAuth.ts:81-155`).
- **Workers-correct rate limiting**: shared D1 counters with atomic upsert-increment (the per-isolate Map trap is documented and fixed), tight namespaces for brute-forceable keyspaces (6-digit webcode: 8/5min), and anonymous write surfaces bounded (crash reports 5/hour/IP) (`src/middleware/rateLimit.ts`).
- **API keys hashed at rest** (SHA-256 + 8-char prefix lookup), plaintext shown once, closed read-only scope enum (`src/auth/apiKeys.ts`).
- **Fail-closed where it counts**: link-confirm hijack guard 503s rather than risking a silent rebind (`src/api/routes.ts:1627-1642`); license revocation status read fails closed to 503 (`src/api/license.ts:78-84`); LuckPerms staff-role lookup fails closed (`gates.ts:405-419`).
- **Privacy engineering on anonymous intake**: crash reports are scrubbed server-side *before* truncation (a truncation can't split a credential), keyed-IP HMAC, hard byte budgets via binary-search truncation (`src/api/v2/crashReports.ts`).
- **Verified secrets hygiene**: `.env` never committed (checked full history), the historically leaked `WEBPANEL_HMAC_SECRET` and `REDIS_PASSWORD` were rotated and stripped (commits `a05eaaa`, `1a5c209`, `d6962d6`), real secrets go through `wrangler secret put`.
- **Proof, not claims**: 633 tests including hostile-shape rejection, auth-flow pins, and signature round-trips with the *real configured* key formats; CI gates typecheck + tests + build + `wrangler deploy --dry-run`.

## Issues

- **[P1] `INTERNAL_SERVICE_TOKEN` committed as a plaintext var — and it grants the v2 admin surface.** `wrangler.jsonc:89` commits the live service token. Per `src/middleware/gates.ts:391-397` and `:465-482`, that token satisfies `isAuthenticated`/`botOrServiceTokenValid`, so `X-Staff-Role: admin` on any v2 staff route (anticheat, audit log, crash-report reads, ticket staff gates) resolves rank 3; it also asserts arbitrary player identity via `X-Mc-Uuid` (`gates.ts:104-114`), gates the license kill-switch (`src/api/license.ts:92`), and speaks-as-server (DMs, changelog). The comment acknowledges the "private repo" posture, but it contradicts this repo's own precedent: REDIS/HMAC plaintext was scrubbed *and rotated* in `d6962d6` for exactly this reason, and `AGENTS.md` says "never commit secrets." Anyone with repo read access (this repo or the frontend repo carrying the same value) gets admin + identity assertion + kill switch. Note the v1 admin routes (`/admin/punish` etc.) are *not* affected — `adminAuthOk` checks `BOT_API_TOKEN`/session only (`routes.ts:170-171`) — the exposure is the v2 surface.
- **[P2] Game-MySQL wire client runs plaintext (`secureTransport: 'off'`).** `src/db/mysqlWire.ts:378` and `src/db/gameMysql.ts:558` open raw TCP to the remote birdflop MySQL. All game data the dashboard/leaderboards serve (balances, transactions, player stats) and the DB credential handshake cross the public internet unencrypted; a captured native-password handshake is offline-brute-forceable and everything else is readable/tamperable on path. This is the backend's primary read plane. If birdflop supports TLS, flipping the flag is a one-line-class fix; if not, it deserves an explicit owner decision in writing.
- **[P2] D1 schema is half-migration, half-runtime-DDL.** `migrations/` has 3 formal files, but `api_keys`, `rate_limit_windows`, `license_revocations`, `client_crash_reports`, `webhook_*`, and `dm_queue` are created by `ensureSchema()` `CREATE TABLE IF NOT EXISTS` on the request path (e.g. `src/auth/apiKeys.ts:56-58`, `src/middleware/rateLimit.ts:24-41`). There's no reviewable/replayable trail for most of the backend's own tables, and first-request-after-deploy pays DDL latency (and a cold-start race, benign only because of `IF NOT EXISTS`).
- **[P3] `sessionCsrfGuard` covers `/api/v2/*` but not the v1 mount.** `src/app.ts:61` registers it only on v2; v1 cookie-authenticated mutations (`/player/cosmetics/equip`, `/player/tags/equip`, `/player/preferences`, `/tickets`, `/action/sellall`) rely solely on the `SameSite=Lax` cookie (`src/auth/jwt.ts:192`). Defense-in-depth inconsistency, not a live hole — and production browsers mostly ride the frontend's own cookie per the `storeAuth` comment (`routes.ts:1776-1784`).
- **[P3] Sessions are stateless with no revocation.** 7-day HS256 JWT, logout only clears the cookie (`routes.ts:406-412`), no jti/denylist — a stolen session is valid to expiry. Modest blast radius (identity reads, not store auth, which is bot-token/X-Mc-Uuid based), but it's the last classic gap in an otherwise thorough auth design.
- **[P3] Webhook-embedded Minecraft UUID bypasses normalization.** `resolveCustomerUuid` returns `customer.minecraft.id` verbatim (`src/paynow/fulfillment.ts:101, 222-224`) — the one dispatch-path UUID that never passes `parseMcUuid`. Signature-verified upstream, so it's PayNow-controlled, but a malformed value becomes `player_uuid` in a signed plugin command; a one-line normalization closes it.
- **[P3] Discord error replies can echo internal error text.** `src/bot/interactions.ts:97-104` sends `err.message` to users via `errorEmbed` — DB/driver strings can reach a player's Discord client. The HTTP API handles this correctly (`app.ts:138-145` returns a generic 500); the bot path doesn't.

## Testing & Tooling

Strong. 71 test files / 633 tests, all green (verified run, ~20s), `tsc --noEmit` clean. Tests verify behavior, not coverage: signature round-trips, retry ladders, auth-flow pins (including the historical truncated-`DISCORD_PUBLIC_KEY` lesson encoded as `discord-public-key.test.ts`), hostile-body rejection, and mount-order claims (the license/client-auth prefix-claim tests). CI runs typecheck + tests + build + wrangler dry-run on every push/PR, plus a monthly dependency-vulnerability watch. AGENTS.md enforces evidence-from-real-runs and "a test that would pass with the fix reverted proves nothing." Gaps: no coverage measurement, no lint config (tsc only), and the D1-fake in tests re-implements just enough SQL to be fragile as queries evolve — acceptable at this scale, worth knowing.

## Top Recommendations

1. **Promote `INTERNAL_SERVICE_TOKEN` to a dashboard Secret** (`wrangler secret put`), remove it from `wrangler.jsonc` vars, and mirror in the frontend worker — the same treatment REDIS/HMAC got in `d6962d6`. This closes the only path where repo read access escalates to admin/identity-assertion/kill-switch.
2. **Turn on TLS for the game-MySQL wire** (`secureTransport: 'starttls'`/`'on'` if birdflop supports it; otherwise tunnel or move the read plane). It's the one data-in-transit exposure left in a system that otherwise treats secrecy carefully.
3. **Write D1 migration files for the runtime-ensured tables** and keep `ensureSchema()` as a no-op safety net, so table definitions are reviewable and replayable like `d1_0001-0003`.
4. **Normalize the webhook-embedded UUID** through `parseMcUuid` in `resolveCustomerUuid` (`src/paynow/fulfillment.ts:222`).
5. **Extend `sessionCsrfGuard` to the v1 mount** (one `app.use('/api/*', …)` next to the v2 registration) so the origin allowlist is uniformly enforced as `gates.ts` intends.
6. **Add minimal session revocation** (jti + D1 denylist checked in `verifyJwt`, or simply shorten to 24h with a refresh) — the last gap between this codebase and a textbook session design.
