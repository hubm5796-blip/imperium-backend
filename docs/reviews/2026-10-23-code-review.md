# Code Review: romanica-backend (2026-10-23)

> **Repo:** Romanica-MC/romanica-backend · **Reviewed commit:** `6c69f05` (master) · **Method:** static review of working tree at HEAD
> Severities: **P0** = broken now · **P1** = likely bug / security hole · **P2** = design debt · **P3** = nice-to-have

## Project Snapshot

Backend for Romanica/ImperiumMC (Rome-themed Minecraft prison server): a Hono/TypeScript API deployed as a Cloudflare Worker serving the website, launcher, and store, plus a gateway-less Discord bot (HTTP interactions + cron). Data plane: Supabase Postgres via Hyperdrive (web-owned tables), direct reads of the live game MySQL via a hand-rolled wire client over `cloudflare:sockets`, D1 for backend-only caches, R2 for gallery images, and an HMAC-signed command bus (MySQL tables, Redis fallback) to the game plugin. Store/real-money goes through PayNow (checkout sessions + signed webhooks). ~38k lines of TS across 241 tracked files, 71 test files / 633 tests (all passing, verified), 47 commits in the last month — very active, with an unusually disciplined 11-round documented audit history under `docs/audit/`.

## Architecture Assessment

The trust model is explicitly designed, not accreted: a single `resolvePrincipal` (session cookie → bearer API key → bot/service token → anonymous) feeds named gates (`requireSelfOrDelegated`, `requireMcIdentity`, `requireStaffRole`) as the only sanctioned entry points (`src/middleware/gates.ts`). Two-tier secrets split bot/service capabilities; delegated identity assertions require the service token specifically. Real-money fulfillment is a three-layer idempotency design (D1 dispatch claims keyed by line index, plugin-side registry dedupe, 500-on-failure so PayNow retries), and currency purchases never trust the backend: the backend only enqueues HMAC-signed `web_queue` rows that the plugin re-validates against the catalog before withdrawing Denarius (`src/api/expansion/webqueue.ts`, `webshop.ts`). The main architectural debt is surface, not structure: `src/api/routes.ts` is 3,535 lines of v1 routes with inline per-route auth conventions alongside the v2 sub-app's uniform gates, and DB schema lives in three places (plugin-owned Postgres, 3 formal D1 migrations, and runtime `CREATE TABLE IF NOT EXISTS` for at least six more D1 tables).

## Strengths

- **Webhook security done right**: PayNow HMAC-SHA256 over `timestamp.body`, 5-minute replay window, timing-safe compare across per-subscription secrets (`src/paynow/webhookVerify.ts`); Discord Ed25519 `verifyKey` before any parsing (`src/bot/interactions.ts:31-40`); vote callbacks keyed per-site with timing-safe compare (`src/api/expansion/webshop.ts:38-43`).
- **Fulfillment idempotency with a release-on-failure path**: dispatch claims are `INSERT … ON CONFLICT DO NOTHING` keyed `(order_id, line_index:product:qty:target)`, and a failed dispatch *deletes* the claim so a transient plugin outage can't permanently eat a paid line (`src/paynow/fulfillment.ts:261-295, 385-404`). Cancel-path webhook failures deliberately 500 so PayNow retries; renewal failures deliberately 200 to avoid retry storms (`src/api/routes.ts:2432-2517`).
- **JWT hygiene beyond the default**: HS256 pinned (alg-confusion blocked), `authMethod` allowlist, lifetime caps enforced against `iat` regardless of `exp` (kills the forwarded-400-day-token class), separate `aud` families so client tokens and session tokens can't replay cross-context (`src/auth/jwt.ts:62-124, 163-185`).
- **Client auth is the real Mojang handshake**: 20-byte single-use challenges consumed atomically before Mojang is even contacted, plus an explicit username↔profile cross-check (`src/api/clientAuth.ts:81-155`).
- **Workers-correct rate limiting**: shared D1 counters with atomic upsert-increment (the per-isolate Map trap is documented and fixed), tight namespaces for brute-forceable keyspaces (6-digit webcode: 8/5min), and anonymous write surfaces bounded (crash reports 5/hour/IP) (`src/middleware/rateLimit.ts`).
- **API keys hashed at rest** (SHA-256 + 8-char prefix lookup), plaintext shown once, closed read-only scope enum (`src/auth/apiKeys.ts`).
- **Fail-closed where it counts**: link-confirm hijack guard 503s rather than risking a silent rebind (`src/api/routes.ts:1627-1642`); license revocation status read fails closed to 503 (`src/api/license.ts:78-84`); LuckPerms staff-role lookup fails closed (`gates.ts:405-419`).
- **Privacy engineering on anonymous intake**: crash reports are scrubbed server-side *before* truncation (a truncation can't split a credential), keyed-IP HMAC, hard byte budgets via binary-search truncation (`src/api/v2/crashReports.ts`).
- **Verified secrets hygiene**: `.env` never committed (checked full history), the historically leaked `WEBPANEL_HMAC_SECRET` and `REDIS_PASSWORD` were rotated and stripped (commits `a05eaaa`, `1a5c209`, `d6962d6`), real secrets go through `wrangler secret put`.
- **Proof, not claims**: 633 tests including hostile-shape rejection, auth-flow pins, and signature round-trips with the *real configured* key formats; CI gates typecheck + tests + build + `wrangler deploy --dry-run`.

## Issues

- **[P1] `INTERNAL_SERVICE_TOKEN` committed as a plaintext var — and it grants the v2 admin surface.** `wrangler.jsonc:89` commits the live service token. Per `src/middleware/gates.ts:391-397` and `:465-482`, that token satisfies `isAuthenticated`/`botOrServiceTokenValid`, so `X-Staff-Role: admin` on any v2 staff route (anticheat, audit log, crash-report reads, ticket staff gates) resolves rank 3; it also asserts arbitrary player identity via `X-Mc-Uuid` (`gates.ts:104-114`), gates the license kill-switch (`src/api/license.ts:92`), and speaks-as-server (DMs, changelog). The comment acknowledges the "private repo" posture, but it contradicts this repo's own precedent: REDIS/HMAC plaintext was scrubbed *and rotated* in `d6962d6` for exactly this reason, and `AGENTS.md` says "never commit secrets." Anyone with repo read access (this repo or the frontend repo carrying the same value) gets admin + identity assertion + kill switch. Note the v1 admin routes (`/admin/punish` etc.) are *not* affected — `adminAuthOk` checks `BOT_API_TOKEN`/session only (`routes.ts:170-171`) — the exposure is the v2 surface.
- **[P2] Game-MySQL wire client runs plaintext (`secureTransport: 'off'`).** `src/db/mysqlWire.ts:378` and `src/db/gameMysql.ts:558` open raw TCP to the remote birdflop MySQL. All game data the dashboard/leaderboards serve (balances, transactions, player stats) and the DB credential handshake cross the public internet unencrypted; a captured native-password handshake is offline-brute-forceable and everything else is readable/tamperable on path. This is the backend's primary read plane. If birdflop supports TLS, flipping the flag is a one-line-class fix; if not, it deserves an explicit owner decision in writing.
- **[P2] D1 schema is half-migration, half-runtime-DDL.** `migrations/` has 3 formal files, but `api_keys`, `rate_limit_windows`, `license_revocations`, `client_crash_reports`, `webhook_*`, and `dm_queue` are created by `ensureSchema()` `CREATE TABLE IF NOT EXISTS` on the request path (e.g. `src/auth/apiKeys.ts:56-58`, `src/middleware/rateLimit.ts:24-41`). There's no reviewable/replayable trail for most of the backend's own tables, and first-request-after-deploy pays DDL latency (and a cold-start race, benign only because of `IF NOT EXISTS`).
- **[P3] `sessionCsrfGuard` covers `/api/v2/*` but not the v1 mount.** `src/app.ts:61` registers it only on v2; v1 cookie-authenticated mutations (`/player/cosmetics/equip`, `/player/tags/equip`, `/player/preferences`, `/tickets`, `/action/sellall`) rely solely on the `SameSite=Lax` cookie (`src/auth/jwt.ts:192`). Defense-in-depth inconsistency, not a live hole — and production browsers mostly ride the frontend's own cookie per the `storeAuth` comment (`routes.ts:1776-1784`).
- **[P3] Sessions are stateless with no revocation.** 7-day HS256 JWT, logout only clears the cookie (`routes.ts:406-412`), no jti/denylist — a stolen session is valid to expiry. Modest blast radius (identity reads, not store auth, which is bot-token/X-Mc-Uuid based), but it's the last classic gap in an otherwise thorough auth design.
- **[P3] Webhook-embedded Minecraft UUID bypasses normalization.** `resolveCustomerUuid` returns `customer.minecraft.id` verbatim (`src/paynow/fulfillment.ts:101, 222-224`) — the one dispatch-path UUID that never passes `parseMcUuid`. Signature-verified upstream, so it's PayNow-controlled, but a malformed value becomes `player_uuid` in a signed plugin command; a one-line normalization closes it.
- **[P3] Discord error replies can echo internal error text.** `src/bot/interactions.ts:97-104` sends `err.message` to users via `errorEmbed` — DB/driver strings can reach a player's Discord client. The HTTP API handles this correctly (`app.ts:138-145` returns a generic 500); the bot path doesn't.

## Testing & Tooling

Strong. 71 test files / 633 tests, all green (verified run, ~20s), `tsc --noEmit` clean. Tests verify behavior, not coverage: signature round-trips, retry ladders, auth-flow pins (including the historical truncated-`DISCORD_PUBLIC_KEY` lesson encoded as `discord-public-key.test.ts`), hostile-body rejection, and mount-order claims (the license/client-auth prefix-claim tests). CI runs typecheck + tests + build + wrangler dry-run on every push/PR, plus a monthly dependency-vulnerability watch. AGENTS.md enforces evidence-from-real-runs and "a test that would pass with the fix reverted proves nothing." Gaps: no coverage measurement, no lint config (tsc only), and the D1-fake in tests re-implements just enough SQL to be fragile as queries evolve — acceptable at this scale, worth knowing.

## Top Recommendations

1. **Promote `INTERNAL_SERVICE_TOKEN` to a dashboard Secret** (`wrangler secret put`), remove it from `wrangler.jsonc` vars, and mirror in the frontend worker — the same treatment REDIS/HMAC got in `d6962d6`. This closes the only path where repo read access escalates to admin/identity-assertion/kill-switch.
2. **Turn on TLS for the game-MySQL wire** (`secureTransport: 'starttls'`/`'on'` if birdflop supports it; otherwise tunnel or move the read plane). It's the one data-in-transit exposure left in a system that otherwise treats secrecy carefully.
3. **Write D1 migration files for the runtime-ensured tables** and keep `ensureSchema()` as a no-op safety net, so table definitions are reviewable and replayable like `d1_0001-0003`.
4. **Normalize the webhook-embedded UUID** through `parseMcUuid` in `resolveCustomerUuid` (`src/paynow/fulfillment.ts:222`).
5. **Extend `sessionCsrfGuard` to the v1 mount** (one `app.use('/api/*', …)` next to the v2 registration) so the origin allowlist is uniformly enforced as `gates.ts` intends.
6. **Add minimal session revocation** (jti + D1 denylist checked in `verifyJwt`, or simply shorten to 24h with a refresh) — the last gap between this codebase and a textbook session design.

### Root-cause analysis of pass-1 findings

**[P1] INTERNAL_SERVICE_TOKEN.** Every backend code path that reads it:
- `src/env.ts:213` — `internalServiceToken: optional('INTERNAL_SERVICE_TOKEN') || (production ? required('BOT_API_TOKEN') : ...)`. **The fallback is a hazard**: deleting the var without setting a secret silently re-merges the delegated principal with the shared `BOT_API_TOKEN` — worse than today.
- `src/middleware/serviceToken.ts:27` — guards DM enqueue (`dms.ts:150`), changelog post/prune (`dms.ts:240,247`), license kill-switch (`license.ts:92`).
- `src/middleware/gates.ts:104` — delegated branch: service token + `X-Mc-Uuid` asserts **any** player identity; `:181` (`requireBot`), `:391-397` (`botOrServiceTokenValid` → the 401 boundary of every v2 `requireStaffRole` route).
- The actual admin escalation is branch 2 of `resolveStaffActor` (`gates.ts:465-482`): bare service token + unauthenticated-in-practice `X-Staff-Role: admin` header yields rank 3 — and `X-Admin-Uuid` (474-481) sets audit attribution with **no verification**. `routes.ts:1789-1796` (`storeAuth`) and `bot/adminRegisterRoute.ts:53` also accept it.
- **Root cause of the commit**: `wrangler.jsonc:56-64` documents Workers Builds wiping dashboard-only vars on Git deploys — but the file's own comment (lines 91-99) states **secrets DO survive Git deploys**; the premise is wrong. Rotation runbook: (1) `wrangler secret put INTERNAL_SERVICE_TOKEN` on `romanica-backend`; (2) same on the frontend worker (reads it via binding in `storeAuth.ts:19`, plaintext at its `wrangler.jsonc:77`); (3) only then remove the var from both `wrangler.jsonc` files (a secret and var can't share a name) and redeploy. Breakage window: delegated X-Mc-Uuid calls, DMs, changelog, kill-switch fail closed until both workers carry the new secret. Never remove the var before both secrets exist (env.ts:213 fallback).

**[P2] Game-MySQL TLS — flipping `secureTransport` is NOT enough and is a silent no-op as-is.** `mysqlWire.ts` has zero TLS plumbing: no `CLIENT_SSL` (0x800) capability, no SSLRequest packet, no `socket.startTls()`, no stream re-acquisition. A correct fix needs, in `wireQuery` (`mysqlWire.ts:372-461`): (1) after `parseHandshake`, check server caps for CLIENT_SSL; (2) send a 32-byte SSLRequest packet (caps|CLIENT_SSL, max-packet size, charset, 23 filler) instead of `HandshakeResponse41`; (3) `await socket.startTls()` and rebuild `WireStream`/writer from the upgraded streams; (4) then send `HandshakeResponse41` and continue (AuthSwitch path 391-402 unchanged). Independently the **Node path is also plaintext**: `gameMysql.ts:47-55` `mysql.createPool` has no `ssl` option. (`gameMysql.ts:558` is only the TCP reachability probe — no data, harmless.)

**[P2] ensureSchema vs migrations — full runtime-DDL inventory: 11 D1 tables, only 1 has a migration file.**
`license_revocations` (license.ts:38-43), `web_dashboard_prefs` (routes.ts:2991), `gallery_posts`+idx (gallery.ts:42-54), `client_crash_reports` (crashReports.ts:58 — dual-sourced with migrations/d1_0003), `dm_queue` (dms.ts:74), `guides`+`guide_votes` (guides.ts:42,54), `api_keys` (apiKeys.ts:43), `guide_comments` (guideComments.ts:24), `action_log` (actionLog.ts:21), rate-limit tables (rateLimit.ts:29, rateLimitV2.ts:69), `webhook_subscribers`/`webhook_deliveries`/`webhook_state` (webhooks/store.ts:61-93 — including an `ALTER TABLE … ADD COLUMN lease_until` whose failure is swallowed at 87-93). Game-MySQL: `bus_kv`, `web_commands`, `web_responses` (busMysql.ts:24-46). A fourth mechanism exists: manual one-shot PG scripts (`migrate-tables.cjs`, `migrate-bot-tables.cjs`). Migration set needs one `d1_0004+` per group in deploy order (D1 `batch()` rejects DDL → sequential prepares), keeping `ensureSchema()` as an idempotent backstop.

**[P3] pass-1 items, concrete fixes:** `sessionCsrfGuard` — hoisting to app-level `/api/*` won't work (it reads `c.get('user')`, set by `attachUser` inside the v1 sub-app, routes.ts:115, which runs after app-level middleware). Fix: register `api.use('*', sessionCsrfGuard)` in `routes.ts` right after `attachPrincipal` (line 123). Webhook UUID: normalize at `fulfillment.ts:101` and `:223` with `parseMcUuid` (or once at `:344` before dispatch). Discord `err.message` echo stands as reported.

### New findings

1. **[P2] Nonce replay protection is a silent no-op on the production bus transport.** `mysqlWire.ts:329` sets `CLIENT_FOUND_ROWS` (0x2) in handshake capabilities. `busMysql.ts:91-98` (`busKvPutOnce`) claims a nonce via `INSERT … ON DUPLICATE KEY UPDATE kv_key = kv_key` and reads `affectedRows === 1` as "first sighting" — but with CLIENT_FOUND_ROWS, an ODKU no-op returns `affected_rows = 1`, so `claimNonceOnce` (`db/redis.ts:185-199`) **always returns true** on the default `BUS_TRANSPORT=mysql` path. Only consumer today: `adminRegisterRoute.ts:63` (HMAC-gated command re-registration replayable within its ±120s window — low direct impact), but the documented B-10 single-use contract is dead and every future consumer inherits it. Tests mask it: `atomic-consume.test.ts:9` forces `BUS_TRANSPORT='redis'`. Fix: drop `CLIENT_FOUND_ROWS` from the caps (nothing needs matched-vs-changed) and verify with a live two-command test.
2. **[P2] Error alerting is disarmed in production, and dashboard-arming is actively wiped.** `wrangler.jsonc:75` declares `STAFF_ALERT_WEBHOOK_URL: ""`; per the file's documented wipe behavior (56-64), a dashboard-set value resets to `""` on the next Git deploy. `errorAlerts.ts:86` `if (!url) return;` short-circuits **before** `sendOwnerDm` (119) — owner-DM leg dead too. Net: `app.onError` (app.ts:140), unhandled-rejection guard (worker.ts), PayNow empty-order (routes.ts:2449), `/errors/report` fan-out (routes.ts:3449) — all invisible outside `wrangler tail`. Cron legs (cron.ts) only `logger.error`. Fix: remove the var declaration, set it as a dashboard Secret, add `alertError` to cron failure paths.
3. **[P3] Command-bus storage grows unboundedly.** `busKvConsume` (busMysql.ts:77-88) only sets `expires_at = 0`, never deletes; `web_commands` rows never deleted; `web_responses` rows for timed-out requests never deleted (`busWaitForResponse` deletes only on read, redis.ts:340/380). Postgres `web_queue` settled/skipped rows: no `DELETE FROM web_queue` anywhere in src (grep-verified).
4. **[P3] Wire client silently truncates result sets at 200 rows** (`mysqlWire.ts:454` `if (rows.length >= 200) break;`). Any `gameQuery` with `LIMIT > 200` returns silently wrong data — leaderboard JOINs are the stated risk class. Only stop on the EOF packet, or throw on suspected truncation.
5. **[P3] Gallery image serving** (gallery.ts:222-227) lacks `x-content-type-options: nosniff` (magic-byte validation itself is sound). R2 objects are never deleted on moderation/privacy-delete — bytes outlive their D1 row; uploads also orphan the R2 object if the D1 insert fails.
6. **[P3] v2 ticket status is free-form**: `PATCH /api/v2/tickets/:id` coerces `status` with `String(v)` (tickets.ts:137-148) while v1 enforces `TICKET_RESPOND_STATUSES` (routes.ts:2661) — a bot typo can strand a ticket outside every `status='open'` filter including the 48h sweep.
7. **[P3] Ticket stale auto-close keys on `created_at` only** (cron.ts:158-176): a 3-day-old ticket with a reply yesterday is force-closed. Key on last activity.
8. **[P3] `paynowErrorReply` (routes.ts:1899-1907) reflects upstream PayNow `err.message` to clients** on 400/502 — leak class if PayNow ever echoes internal context.
9. **[P3] D1 test fakes are per-test hand-rolled stubs** keyed on SQL prefixes (`api-keys.test.ts:19-40`); ON CONFLICT semantics, LIMIT binding, type affinity, `batch()` DDL rejection, ALTER failure modes, and concurrency are unverified against real D1. One smoke suite against real D1/Miniflare would close this.
10. Cosmetic: `redis.ts:11` `usePgBus()` routes to the **MySQL** bus and reads `process.env.BUS_TRANSPORT` directly, bypassing the env module; the `'postgres'` default literal contradicts the comment above it.

### Cross-repo notes

- **Command bus end-to-end:** v2 commands are HMAC-SHA256 over `type|ts|nonce|requestId|sha256(stableStringify({type,request_id,ts,nonce,payload}))` (`redis.ts:223-247`), 30s window. `web_queue` rows are signed `v1|kind|requestId|uuid|username|site|sku|quantity|createdAtSec` (`webqueue.ts:49-62`); the plugin must re-derive pricing from signed `sku`/`quantity` (`payload` deliberately unsigned). **Key rotation has no key-id**: `WEBPANEL_HMAC_SECRET` is shared by the Redis bus, game-MySQL bus, `web_queue` rows, and admin-register HMAC — a rotation requires simultaneous plugin+worker swap; queued-but-unconsumed rows signed with the old key get marked `skipped`. Recommend a `kid` field + dual-key verification on the plugin before the next rotation.
- **Transport split-brain (see the cross-repo audit):** backend default is the MySQL bus, whose `web_commands`/`web_responses` the plugin never reads — the plugin only speaks Redis.
- Plugin downtime: dispatchers are request/response with 5-10s timeouts, callers degrade to 501/502; PayNow fulfillment releases line claims on failure so retries re-dispatch. No dead-letter surface or queue-depth alert.
- Launcher/client contracts and the full audit table: see [the cross-repo audit doc in RomanicaPlugin](https://github.com/Romanica-MC/RomanicaPlugin/blob/master/docs/reviews/2026-10-23-cross-repo-audit.md).

### Revised recommendations

1. **Rotate `INTERNAL_SERVICE_TOKEN` into dashboard Secrets on both workers** (runbook above); order matters — vars must not be removed before both secrets exist, or `env.ts:213` silently re-merges onto `BOT_API_TOKEN`.
2. **Remove `CLIENT_FOUND_ROWS` from the wire-client capabilities** (mysqlWire.ts:329) and add a real-semantics test for `busKvPutOnce` — until then the B-10 replay contract is a no-op on the production transport.
3. **Implement MySQL TLS properly** (SSLRequest + `startTls()` in mysqlWire.ts — a flag flip alone is a silent no-op), plus an `ssl` option on the Node mysql2 pool (gameMysql.ts:47).
4. **Arm error alerting**: delete `STAFF_ALERT_WEBHOOK_URL` from `wrangler.jsonc` vars, set it as a dashboard Secret, call `alertError` on cron leg failures.
5. **Consolidate schema + queue hygiene**: one migration set covering the 11 runtime-DDL D1 tables (replace the ALTER-swallow), and pruning for consumed `bus_kv`, timed-out `web_responses`, settled `web_queue` rows — or document plugin-side pruning as the owner of record.

### New findings

1. **[P1] Webhook tailer cursor is lexicographic against a numeric id — events silently stop flowing at every digit boundary.** `src/webhooks/tailer.ts:78` filters `id::text > $1`, but `web_events.id` is `BIGSERIAL`; once the cursor reaches `'999'`, every 4-5 digit id sorts below it and the tailer wedges permanently (zero rows, no error). All `player.rankup`/`player.prestige`/`war.result`/`season.roll` webhook deliveries die. The sibling SSE poller does it correctly (`sse/poller.ts:182-197`, numeric `id > $1`). Fix: numeric cursor + an alert when the tailer scans 0 events while `MAX(web_events.id)` advances.
2. **[P2] `playerQuery` never sets the RLS session context on the Workers (production) path.** `src/db/pool.ts:145-151`: `set_config('imperium.uuid', …)` runs on one connection, the statement on a **second fresh connection** that never received it. Masked today only because the Hyperdrive role bypasses RLS — activating the documented `imperium_app` restricted-role plan would make every `playerQuery` see 0 rows (dashboard prefs, discord links, tickets, web_queue), silently. Also two connections per query. Fix: `set_config` + statement on one client, matching the Node branch; test against the restricted role **before** flipping.
3. **[P2] The internal Discord-bot webhook subscriber is never seeded — the role-sync push pipeline shipped inert.** `seedInternalBotSubscriber` (`webhooks/store.ts:301-311`) has zero call sites; the `'discord-bot'` subscriber that should receive `subscription.updated`/`player.prestige`/`player.rankup` never exists unless hand-inserted into D1. Wire it at isolate init behind `WEBHOOK_BOT_URL`+`ROLE_WEBHOOK_SECRET`, or delete the push path.
4. **[P2] v1 `POST /api/tickets` lacks every anti-abuse control its v2 twin has** — no writeRateLimit, no open-ticket cap, free-form category; the frontend's `tickets/submit` forwards raw bodies straight here. Unbounded ticket growth + staff-queue flooding + Discord threads via the cron sweep. Copy the v2 trio (`tickets.ts:47,64,67-78`).
5. **[P3] Webhook subscriber URLs: any scheme, any host** (`webhookAdmin.ts:28` `z.string().url()`; fetched verbatim with redirects) — same-trust today, but pin https + host allowlist before the planned api_key/public owner migration.
6. **[P3] Three more unbounded tables**: `webhook_deliveries` (delivered/dead rows never deleted), `dm_queue` (sent/failed), and `discord_dedupe` (one Postgres row **per minute** for cron claims, ~525k rows/year) — fold into the pruning migration.
7. **[P3] Cron leg isolation hole**: `runTicketSweep` is awaited without its own try/catch (`bot/cron.ts:110`) — a network-level throw skips the DM-queue leg for that minute, every minute it persists.
8. **[P3] Gallery upload buffers the entire multipart body before the 5 MB check** (`gallery.ts:178-187`) — a near-100MB request materializes in isolate memory; the 3/day quota check is also pre-insert TOCTOU. Check Content-Length / stream-truncate first.
