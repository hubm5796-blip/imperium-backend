# Nitpick pass: romanica-backend (2026-10-24)

> Owner-requested sweep for every small thing, on top of the 2026-10-23/24 reviews in this folder. Nothing here repeats those docs unless it's still live. Checks were scripted greps and live `curl`s run on 2026-10-24. Each item names the file:line or URL that shows it. Only the items marked as checked live were run against production.

## Findings

- routes.ts:2609-2610 and 3196-3197 (/tickets, /marketplace/listings): `Math.max(1, parseInt(x))` lets NaN through. `?page=abc` gives NaN, and the NaN reaches LIMIT/OFFSET. The v2 routes use `|| 1` (adminPanel.ts:38, gallery.ts:120, guides.ts:82). One helper for both.
- routes.ts tickets: `status` query param goes into SQL as a parameter, but it's never checked against the enum, so a typo returns an empty page instead of a 400.
- bot/embeds/kit.ts:36 `bustUrl()` has no callers and points at crafatar, which returns 422 for names (verified: `crafatar.com/renders/head/Notch` → 422) even though the parameter is named `uuidOrName`. Delete it.
- bot/commands/changelog.ts:33,46: the Discord embed footer says `imperiummc.net`. Players see it.
- db/changelogStore.ts:51,56,66: published changelog text still says "ImperiumMC" and "English always stays at imperiummc.net". Players see it.
- README.md: titled "ImperiumMC Backend". It still describes Redis as the fallback through `BUS_TRANSPORT=redis` without warning that the live plugin doesn't listen there. Add "never set this".
- package.json: name `imperium-backend`, description "ImperiumMC backend API + Discord bot", version 1.0.0 placeholder.
- package.json: `cookie` is a dependency with zero imports. `@hono/zod-validator` 0.4 (latest 0.9.1) and `zod` 3 (latest 4.6) lag.
- `.env.example` documents `CORS_ORIGINS`, which nothing reads. CORS is a hardcoded `ALLOWED_BROWSER_ORIGINS` set (app.ts:32).
- CI runs Node 22, but `engines`, `.nvmrc` and `.node-version` all say 26.5.1.
- fetch without a timeout: auth/discord.ts (2), bot/adminRegisterRoute.ts (1), bot/interactionShim.ts (2). If Discord hangs, the request hangs until the Worker is killed.
- changelogStore.ts:166: post ids use `Math.random()`. That's harmless for ids, but the repo replaced Math.random elsewhere on principle (routes.ts:3317, moderation.ts:122), so use `crypto.randomUUID()` for consistency.
- Redis/KV key names are still `ImperiumMC:*` (redis.ts:26-46, adminRegisterRoute.ts:27). They're protocol-locked to the plugin, so leave them, but document that in one place so nobody "fixes" one side.
- docs/: AUDIT_GLM_COMPLAINTS.md, audit/ROUND-2..11 and the 2026-10 reviews overlap and contradict each other (the bus split-brain). Add a docs/README.md saying which is current, or archive the old rounds.
- routes.ts is 3,535 lines and db/pool.ts 1,416. The split plan is in the modernization blueprint; noting it here so it isn't lost.
- 14 `any` casts outside tests. 20+ `catch {}` / `.catch(() => {})` sites (publicProfiles.ts has 10). Each should at least `log.warn` with a tag.
- rateLimit.ts:113 and rateLimitV2.ts:103 both do probabilistic cleanup at 2%. Two limiter implementations exist side by side; pick one.

## Cross-repo inconsistencies

- **Two vote-site lists.** The website has 9 sites (`romanica-frontend/src/lib/site.ts:26-34`); the plugin has 8 plus 34 (`vote-sites.yml`), and most of the 34 are placeholders. Keep one list, in the backend or the plugin config, and have the other read it.
- **Game version.** The plugin `api-version` is 26.2, and the pack and plugin config say `26.2`. The launcher and client ship 26.3, and the website FAQ meta says "1.8–26.2". Settle one statement of "server runs X, client Y, joinable from Z" and use it everywhere.
- **Social handles** are `@PlayImperiumMC` / `r/ImperiumMC` on the website (`site.ts:11-17`, `llms.txt:147-149`). This is the owner's call: rename the accounts, or keep them and note it.
- **"ImperiumMC" in player-visible strings:** Discord changelog footers (backend), the pack menu description (pack), mod-menu source/issue links (client), and launcher support links. Each is listed in its repo's doc.
- **Protocol-locked old names that must NOT be renamed one-sided:** Redis keys `ImperiumMC:*`, permission nodes `imperiummc.*`, mod id and channels `imperiumclient:*`, env var `IMPERIUMMC_HMAC_SECRET`. Rename them only in a coordinated change across both sides.
